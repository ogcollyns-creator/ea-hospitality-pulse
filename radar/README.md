# Source radar

Change detection over ~137 upstream sources across Kenya, Uganda, Tanzania, Zanzibar
and Rwanda. Stdlib Python plus SQLite — nothing to install.

## Why it exists

Search engines rank by relevance, not recency. On 28 July 2026 a midday Pulse run
searched by hand, found nothing publishable, and nearly ran a WTTC release that a
search engine presented as same-day news — the page itself was dated 15 June.

Hence `items.first_seen_ts`: the moment *we* observed an item. Written once, never
updated. It is the only date the recency gate runs on. The page's claimed date is used
solely to disqualify — when something first seen today claims a date six weeks back,
that gap is the finding.

**The claimed date is a claim. First-seen is a measurement.**

## Commands

```bash
python3 radar/scan.py restore                       # replay ledger — do this first
python3 radar/scan.py scan --workers 10 --slot midday
python3 radar/rank.py --slot midday                 # -> out/candidates.{json,md}
python3 radar/render.py                             # -> ../radar.js  (feeds radar.html)
python3 radar/scan.py export                        # append to out/items.jsonl
python3 radar/scan.py health                        # sources that stopped answering
python3 radar/scan.py status
```

`--only id1,id2`, `--force`, `--limit N` on scan. `--since-hours N`, `--top N` on rank.
`RADAR_DELAY` overrides the per-host courtesy delay — fixtures only, never live sources.

## Layout

| File | Role |
|---|---|
| `registry.json` | the source registry (generated by `_gen_registry.py`, hand-editable) |
| `store.py` | schema, resume state, first-seen semantics |
| `fetcher.py` | robots.txt, per-host delay, conditional GET, circuit breaker |
| `extract.py` | RSS/Atom, sitemap, HTML anchors, PDF text, date parsing |
| `scan.py` | orchestrator |
| `rank.py` | scoring, dedupe against `editions-src/`, candidate feed |
| `render.py` | writes `../radar.js` |
| `out/items.jsonl` | **append-only ledger — the durable record** |
| `radar.db` | warm cache, gitignored, rebuildable via `restore` |

## Two-file durability model

The SQLite database is a *cache*: it holds etags and content hashes so most sources
answer 304. Losing it costs bandwidth, not history.

`out/items.jsonl` is the *record*. It is append-only, committed, diffs cleanly, and can
be replayed by anything including a human with grep. `scan.py restore` rebuilds the
database from it with original first-seen timestamps intact, and is idempotent.

Committing a multi-megabyte binary twelve times a day would bloat the repo for no gain;
committing a text ledger costs a few kilobytes and is auditable.

## Politeness

1. robots.txt fetched once per host per day and obeyed. An explicit `Disallow` ends it.
2. One request per host per crawl-delay window, six seconds minimum. Sources are grouped
   by host and each host is handled by exactly one worker, so `--workers` widens the
   front across hosts and can never increase pressure on any one of them.
3. Every request conditional. An unchanged source costs one 304 and no bandwidth.
4. Documents opened only when newly seen, capped per source per run.

## Detection tiers

Negotiated per source at first contact, then cached in `sources.resolved_method`:

1. **RSS/Atom** — auto-discovered via `<link rel=alternate>`. Cheapest, carries real
   publication dates.
2. **HTML anchors** — headline-shaped links from an index page. Most gazettes and
   regulator notice pages have no feed; their anchors *are* the items.
3. **Page hash** — fallback when no headline-shaped anchors exist. Emits a `page-change`
   item. Detects that the page moved, not what changed; a human reads the diff.
4. **PDF text** — newly-seen documents are opened and text-extracted for keyword and
   date scanning. Not layout-faithful, and not trying to be.

## Scoring

Every candidate carries its full component breakdown, because a ranking you cannot argue
with is one an editor quietly stops trusting.

`tier` · `category` · `lead` (head start over mainstream press) · `relevance` (hospitality
lexicon) · `freshness` (decays over 18h from first-seen) · `corroborated` (+10, source
date agrees) · `undated` (−6) · `stale_trap` (−10/−25/−60 at 3/7/21 days) · `shock` (+18)
· `already_covered` (−40 in 7d, −70 today) · `page_change` (−4).

Dedupe uses **containment**, not Jaccard: a three-word radar headline against a ten-word
edition headline scores near zero on Jaccard even when it is plainly the same story.
Headline extraction is shared with `recent_topics.py`, so the radar and the coverage
check can never disagree.

## Adding a source

```json
{"id":"ke-example","name":"Example Regulator","url":"https://example.go.ke/notices/",
 "tier":1,"country":"KE","category":"regulator","method":"html","cadence_min":180,
 "lead_days":7,"segments":["city","bush"],"slots":["morning"],
 "why":"One line on why an operator should care.","frag":""}
```

Registry edits never reset runtime state. Sources removed from the registry are disabled,
not deleted — history stays queryable and re-adding restores it.

`frag` is an optional substring; everything before it is ignored when diffing. Use it when
navigation or a "latest tweets" block causes false positives.

## A dead source is a blind spot, not a quiet news day

`scan.py health` is an editorial risk register, not an ops dashboard. A gazette that
silently 403s for a fortnight produces exactly the same empty feed as a fortnight with no
gazette notices — only the health report tells them apart. Check it before accepting any
thin edition.

## Installing the scheduled workflow

`radar/workflow-radar-scan.yml` is the GitHub Action that polls the sources. It is not
committed to `.github/workflows/` because the publishing token lacks the `workflow`
scope. Install it once, either way:

```bash
mkdir -p .github/workflows
cp radar/workflow-radar-scan.yml .github/workflows/radar-scan.yml
git add .github/workflows/radar-scan.yml && git commit -m "Add radar scan workflow" && git push
```

That push needs a token with `workflow` scope. Alternatively paste the file into
**GitHub → Actions → New workflow → set up a workflow yourself**, which needs no token
at all.

Until it is installed, run the radar by hand from a clone — the commands above work
unchanged.
